# Отчет по проекту "Музыкальная библиотека"

## 1. Постановка задачи

Цель: Разработать клиент-серверную информационную систему "Музыкальная библиотека", предназначенную для централизованного хранения, структурированного управления и анализа музыкальных треков и их метаданных.

Система не работает с аудиофайлами напрямую, а хранит только описательную информацию о треках.

## 2. Логическая модель базы данных

### Основные сущности:

1. **Пользователь (user)** - информация о пользователях системы
2. **Жанр (genres)** - справочник музыкальных жанров
3. **Исполнитель (artists)** - справочник исполнителей
4. **Трек (tracks)** - информация о музыкальных треках
5. **Коллекция (collections)** - персональные коллекции треков
6. **Связь коллекция-трек (collection_tracks)** - состав коллекций
7. **Любимые жанры (user_favorite_genres)** - любимые жанры пользователя
8. **Любимые исполнители (user_favorite_artists)** - любимые исполнители пользователя
9. **Журнал аудита (audit_log)** - история операций

### Описание связей:
- Один пользователь может иметь много треков (1 ко многим)
- Один пользователь может иметь много коллекций (1 ко многим)
- Один трек может принадлежать нескольким коллекциям (многие ко многим через промежуточную таблицу)
- Один трек имеет одного исполнителя и один жанр (многие к одному)
- Один пользователь может отмечать несколько любимых жанров и исполнителей (многие ко многим)

## 3. Краткое описание средств реализации приложения

### Серверная часть:
- **Язык программирования**: Python
- **Веб-фреймворк**: Flask
- **База данных**: PostgreSQL
- **Драйвер базы данных**: psycopg2
- **СУБД**: PostgreSQL с поддержкой JSONB для хранения деталей аудита

### Клиентская часть:
- **Язык разметки**: HTML5
- **Каскадные таблицы стилей**: CSS3
- **Скриптовый язык**: JavaScript (ES6+)
- **Архитектура**: клиент-серверная с REST API

### Архитектурные особенности:
- Все операции с базой данных выполняются через хранимые процедуры
- Реализована модель клиент-сервер с сервером базы данных
- Поддержка ролевой модели (пользователь/администратор)
- Система аудита всех операций

## 4. Описание реализованных процедур, функций, триггеров

### Хранимые процедуры:

1. **add_user** - добавление нового пользователя с созданием записи в журнале аудита
2. **add_genre** - добавление нового жанра с записью в журнал аудита
3. **add_artist** - добавление нового исполнителя с записью в журнал аудита
4. **add_track** - добавление нового трека с проверкой прав доступа и записью в журнал
5. **add_collection** - добавление новой коллекции с записью в журнал
6. **add_track_to_collection** - добавление трека в коллекцию с проверкой принадлежности
7. **get_user_tracks** - получение треков конкретного пользователя
8. **get_all_tracks** - получение всех треков (только для администраторов)
9. **search_tracks** - поиск треков по различным критериям
10. **update_track** - обновление информации о треке с проверкой прав доступа
11. **delete_track** - удаление трека с проверкой прав доступа
12. **get_user_profile** - получение информации профиля пользователя
13. **update_user_profile** - обновление профиля пользователя
14. **add_favorite_genre** - добавление любимого жанра
15. **add_favorite_artist** - добавление любимого исполнителя
16. **get_user_collections** - получение коллекций пользователя
17. **get_collection_tracks** - получение треков в коллекции
18. **get_audit_log** - получение журнала аудита (только для администраторов)

### Триггеры:

1. **validate_bpm** - проверяет, что значение BPM находится в разумном диапазоне (20-300)
2. **validate_duration** - проверяет, что длительность трека положительна
3. **auto_create_favorite_collection** - автоматически создает системную коллекцию "Любимые треки" при регистрации пользователя

## 5. Скриншоты интерфейса приложения

*Примечание: В этом текстовом отчете скриншоты представлены в описательной форме*

### Основные страницы приложения:

1. **Страница аутентификации**:
   - Форма входа с полями логина и пароля
   - Форма регистрации с полями для создания нового аккаунта

2. **Личный кабинет пользователя**:
   - Вкладка "Профиль" - информация о пользователе и возможность редактирования
   - Вкладка "Мои треки" - список треков с возможностью добавления, редактирования и удаления
   - Вкладка "Поиск треков" - форма поиска с фильтрами по различным критериям
   - Вкладка "Коллекции" - список коллекций с возможностью создания новых

3. **Интерфейс администратора**:
   - Вкладка "Администрирование" - просмотр всех треков в системе
   - Вкладка "Журнал аудита" - история всех операций в системе

### Особенности интерфейса:
- Полностью на русском языке
- Адаптивный дизайн для разных устройств
- Интуитивно понятные элементы управления
- Четкая структура навигации по разделам

## 6. Технические особенности реализации

### Безопасность:
- Все операции с базой данных выполняются через хранимые процедуры
- Проверка прав доступа к данным (пользователь может работать только со своими данными)
- Разграничение прав доступа (пользователь/администратор)
- Хеширование паролей с использованием алгоритма Werkzeug

### Аудит:
- Все операции добавления, изменения и удаления записываются в журнал аудита
- Фиксируется дата операции, тип операции, таблица, ID записи и пользователь
- Поддержка детализации операций с хранением JSON-объектов с деталями

### Функциональность:
- Поддержка CRUD-операций для всех основных сущностей
- Поиск и фильтрация треков по различным критериям
- Персонализированные коллекции треков
- Управление профилем пользователя
- Система любимых жанров и исполнителей

## 7. Заключение

Разработанная система "Музыкальная библиотека" полностью соответствует поставленной задаче и требованиям. Она обеспечивает:

- Централизованное хранение информации о музыкальных треках
- Управление данными через интуитивно понятный веб-интерфейс
- Поддержку пользовательских коллекций и персонализации
- Аудит всех операций с данными
- Разграничение прав доступа между обычными пользователями и администраторами
- Безопасное взаимодействие с базой данных через хранимые процедуры

Система может быть легко масштабирована и дополнена новыми функциями в соответствии с требованиями.
